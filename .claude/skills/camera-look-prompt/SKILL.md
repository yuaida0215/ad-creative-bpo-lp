# Camera Look Prompt

絵コンテやシーン仕様の各カットに**カメラの層**（カメラ・レンズ・光・ピント・動き）を足して、
動画生成AIにそのまま投げられる英語プロンプトにするSkill。

ベースは Promptwise Field Guide 01「5 Camera & Lens Setups for AI Video」。
これを Snafty の広告動画（EC/D2C・縦型・量産・パートナー制作）向けに組み直している。
広告向けに足したルールには【Snafty】と付けている。

## 前提（厳守）

- **カメラ名・レンズ名は「見た目の合図」にすぎない。** 実機を再現するものではなく、同じ語でもモデルによって解釈がブレる。
  効くのは名前のあとに書く**見え方の条件**、つまり光源の位置、距離、ピント対象、動きのきっかけ。
- **形容詞を足すより、原因を書く。** たとえば「美しいボケ」ではなく「被写体の数m後ろに小さな灯り」と書く。
- **【Snafty】1本の動画に使うカメラパッケージは1つだけ。** カットごとに変えるのは焦点距離・T値・光・動きだけにする。
  カメラ名をカットごとに変えると、ルックが揃わない。
- **肯定形で書く。** 「no camera movement」ではなく「locked camera」。
  ネガティブ欄は、同じ破綻が何度も出るときの補助にだけ使う。
- プロンプト本文は英語で書く。人が確認するための「狙い」メモは日本語で書く。

## ワークフロー

### Step 1: 入力を読む（聞かずに埋める）

会話や添付から、以下を推定で埋める。どうしても決まらない項目だけ、最大2問にまとめて聞く。

| 項目 | 例 / 既定値 |
|---|---|
| カット一覧 | 絵コンテのコマ、シーン仕様の Scene 1〜8、単発カット |
| 各カットの主役 | 商品 / 人物の表情 / 手元の動作 / 空間 / キャラクター |
| 生成方式 | **既定は i2v**（キーフレーム画像 → 動画）。t2v なら出力2ブロックを連結して使う |
| 縦横比 | **既定は 9:16**。ほかに 4:5 / 1:1 / 16:9。縦横比はツールのパラメータで指定する |
| ツール | Kling / Seedance / Higgsfield / Runway / Veo など |
| 尺の配分 | 全体の尺をカット数で割る。生成はツールの単位（例：5秒）で出し、編集で詰める |
| 参照画像 | 商品の実物写真、キャスト／キャラクターの参照画像があるか。人物をカット間で揃える必要があるのに参照画像がなければ、最初にキャスト画像を1枚作って identity 参照にするよう注記する |
| 制約 | 色再現が必須のSKUか、ブランドのトーン、シリーズのルック表がすでにあるか |

### Step 2: カメラパッケージを1つ決める

詳細は `references/presets.md`。動画全体の主目的でパッケージを1つ選ぶ。

| 主目的 | パッケージ |
|---|---|
| 商品をクリアに、色を正確に見せる（コスメ・食品・ガジェット・商品デモ） | **P2 CLEAN** |
| 素材感・手触り・ブランドの温度を出す（アパレル・革・ニット・木・手仕事） | **P1 FILM** |
| 人物の表情や瞳で引っぱる（感情・語りかけ・使用後の満足） | **P4 PORTRAIT** |
| 空間ごと見せる（生活シーン・店舗・部屋の中で起きる出来事・キャラ物） | **P5 NATURAL DEPTH** |
| 夜・ネオン・店舗照明で世界観をつかむ | **P3 ANAMORPHIC** |

- 迷ったら「**この動画で一番ピントが必要なものは何か**」で決める。商品なら P2、瞳なら P4、部屋なら P5。
- シリーズ物でルック表（`references/series-look.md`）がすでにあれば、それに従う。
- **ほかのパッケージ向きのカットが混ざっても、カメラ名は変えない。** そのパッケージの「狙う見え方」のフレーズだけを借りる。
  例：P2 の動画に入る家族の食卓カットなら、P5 の `the room behind remains recognizable but softly separated` だけを借りる。
- 【Snafty】ここでは王道のパッケージを1つ選ぶ。それとは別に、**外しとして UGC／スマホルック**（presets.md の末尾）を
  ABテスト用に提案するかどうかを、最後に一言だけ添える。シネマ調が常にCTRで勝つとは限らない。

### Step 3: カットごとに6スロットで組む

次の順番で書く。最初に「何が起きるか」を書き、カメラの話はそのあとにする。

1. **SHOT & ACTION**：ショットサイズ、被写体、何が起きるか
2. **CAMERA & LENS**：パッケージ名、焦点距離、T値（presets.md にある、そのパッケージのショット別の表から選ぶ）
3. **LIGHT**：光源（窓・ランプ・看板など）、当たる方向、質
4. **SURFACES**：質感を見せたい素材を2〜3個だけ名指しする（「hyper-detailed everything」は使わない）
5. **FOCUS & DEPTH**：ピントを合わせるもの、被写界深度、背景に何がどの距離にあるか
6. **MOVEMENT**：カメラの動きと、その**きっかけ**（被写体の動作に反応させる）。動かさないなら `locked camera`

焦点距離とT値は、presets.md の各パッケージの表（引き／ミディアム／寄り／ディテール）から選ぶ。
深さについては、次の優先順位で決める。

1. **商品が画面の中で読める必要があるカットは、T4前後で深くする。** 表情や余韻のカットであっても、これを優先する。
2. 商品が画面の外にあるか、背景として小さく映るだけなら、表情や余韻のカットは開放寄りで浅くしてよい。
3. 商品自体が動くカット（持ち上げる、注ぐ）は、カメラが追い、動きが止まった瞬間にピントを確定させる。

KEYFRAME では、人物がいないカットから人物用の語（`natural skin tones` など）を外す。
LIGHT スロットの光源はシーンに合わせて差し替える（例：夜の室内なら `warm practical light from {lamp}`）。

「soft」と書くときは、どのソフトかをはっきりさせる。影の縁（soft light）、背景のボケ（softly defocused background）、明部へのなだらかな移行（gentle highlight roll-off）の3つがあり、どれを選んでも瞳や商品はシャープに保つ。

### Step 4: 出力する

冒頭にパッケージを1行で宣言する（理由も1行）。そのあと、カットごとに次の形で出す。

````
## LOOK: P2 CLEAN — Sony VENICE 2 / ZEISS Supreme Prime（理由：商品の色と質感を正確に見せるため）

### Cut 1｜導入 — 狙い：〈日本語1行〉
**KEYFRAME（画像生成用）**
```text
...
```
**MOTION（i2v用）**
```text
...
```
````

- **KEYFRAME** にはスロット1〜5を入れる。「見た目」は全部ここに入れ、ルックもここで確定させる。カメラの動き（スロット6）は入れない。
- **MOTION** には**変わること**だけを書く。順番は、アクション → カメラの動き → ピントの移動 → 足りない要素。
  画像に写っているものを全部書き直すと、動きの指示と競合する。2〜3文を目安にする。
- **リビール型のカット**（フタを開ける、皿を返すなど、見せ場がカットの途中で現れるもの）では、見せ場の完成形をモデル任せにしない。
  - 開始と終了のフレームを指定できるツールなら、見せ場の完成形を **END FRAME（画像生成用）** として3つ目のブロックに出す。
  - 指定できないツールなら、開始フレームを「見せ場がすでに一部見えている瞬間」にする。
- t2v で使うときは、KEYFRAME のあとに MOTION をつなげて1本にする。
- **音**：既定では、SE は編集で乗せる。ネイティブ音声を使うときだけ、MOTION の末尾に `Sound: …` を1文足す。
- 長い前置きや解説はつけない。すぐ投げられることを優先する。
- 全カットのあと、次の順で短く添える。
  1. **外し案**（UGC／スマホルック版でABテストするか。1行）
  2. **推定で埋めた前提**（生成方式、縦横比、尺の配分、時間帯、キャストの有無など。1〜3行）
  3. 一度だけ「**シリーズ用のルック表（パートナー配布用）も出しますか？**」と聞く。
     シリーズ前提が会話で明らかなら、聞かずに `references/series-look.md` の形式で添付してよい。

出力の実例は `references/examples.md` にある。

### Step 5: 直すとき

`references/principles.md` のトラブル早見表を使う。

- **1回に1要素だけ変える。** 同じシーンで比較する。1回の生成結果だけでフレーズを判断しない（2〜3本は出す）。
- クライアントの「なんか安っぽい」「AIっぽい」といった感覚的な言い方は、早見表の「言われ方」列で症状に翻訳し、変える1変数を決めてから直す。

## 広告（EC/D2C）での追加ルール【Snafty】

- **商品の正確さは入力画像で担保する。** ラベルや形は実物写真から作ったキーフレームで i2v する。
  文字はプロンプトで描かせず、テロップやロゴは編集で乗せる。
- **色再現が必要な商品カットは `neutral color balance`（P1 なら `daylight-corrected color`）にする。** フィルム調の色転びを商品に乗せない。
  厳密に守るのは、SKU の色が返品やクレームにつながる商材（コスメの色番、アパレルの色展開など）。
  食品は `neutral color balance with a gentle warm tint` まで許容する。美味しそうに見えることを優先してよい。
- **商品デモは被写界深度を深め（T4前後）にして、顔と商品の両方を読ませる。** 優先順位は Step 3 のとおり。
- **商品は止まってからピントを移す**（`as the bottle comes to rest, focus shifts to the label side`）。商品自体が動くカットは、追ってから止まった瞬間に確定させる。
- **縦 9:16 でアナモルフィックを使う場合は、「楕円ボケ」と「横フレア」という癖だけを借りる。** ワイドの画面比は持ち込まない。
- **冒頭1〜2秒のカットは、最初のフレームから動作が起きている状態にする。** きっかけのない、ゆっくりした寄りから入らない。

## 注意

- キャラクターや人物の参照画像には役割を明記する（例：`reference image 1 = identity only`）。
  キャラクターシートの背景やポーズを持ち込ませない。デザイン規定の厳しいキャラクターは、外見を文章で描写し直さず、参照画像に任せる。
- 廃止ツール（heart-hack / Lovart）には言及しない。
- クライアント名・案件固有の設定は、このSkillのファイルに書き込まない（公開リポジトリでも管理しているため）。
  案件ごとのルック表は、会話内または非公開の場所で管理する。
